================================================================================
  1. PRÉSENTATION DU PROJET
================================================================================

1.1 Contexte et Origine du Besoin
----------------------------------
Dans le cadre de l'organisation d'activités institutionnelles (formations,
ateliers, réunions, séminaires), la collecte manuelle des informations de
présence des acteurs présente plusieurs limites : lenteur du processus, erreurs
de saisie, données incomplètes, difficultés d'archivage et de traitement
ultérieur.

Afin de moderniser et sécuriser ce processus, il est nécessaire de mettre en
place une application web permettant de numériser entièrement la collecte,
l'archivage et l'exploitation des données de présence, en intégrant la capture
de justificatifs d'identité (Carte Nationale d'Identité).


1.2 Objectifs Généraux
-----------------------
  - Numériser la collecte de présence via un formulaire web mobile accessible
    par QR Code
  - Centraliser et sécuriser les données des participants par activité
  - Automatiser la génération de documents de sortie (listes Excel, PDF CNI,
    listes de présence signées)
  - Offrir un tableau de bord de pilotage à l'organisateur


1.3 Périmètre du MVP
---------------------
Le présent cahier des charges couvre la version MVP (Minimum Viable Product)
de l'application, qui inclut :

  - La gestion des activités (création, suivi, fermeture)
  - La génération et utilisation de QR codes
  - Le formulaire de collecte avec upload de photos CNI
  - Les exports Excel et PDF
  - L'authentification de l'organisateur


1.4 Parties Prenantes
----------------------
  Acteur                    Rôle                          Interaction
  ------------------------  ----------------------------  ----------------------
  Organisateur              Crée et gère les activités    Interface web admin
  Participant               S'enregistre à une activité   Formulaire via QR Code
  Administrateur technique  Déploie et maintient          Accès SSH + Admin Django

  2. FONCTIONNALITÉS DÉTAILLÉES

------------------------------------------------------------------------
  MODULE 1 — AUTHENTIFICATION & GESTION DES COMPTES
------------------------------------------------------------------------

[AUTH-01] Connexion Organisateur                 | Priorité : HAUTE | Complexité : Faible
  L'organisateur se connecte via un formulaire login/mot de passe.
  L'application génère un token JWT stocké côté client (localStorage).
  Toutes les routes du tableau de bord sont protégées.

[AUTH-02] Déconnexion & Expiration de Session    | Priorité : HAUTE | Complexité : Faible
  Le token JWT expire après 8 heures. L'organisateur peut se déconnecter
  manuellement. À l'expiration, l'utilisateur est automatiquement redirigé
  vers la page de connexion.

[AUTH-03] Réinitialisation du Mot de Passe       | Priorité : MOYENNE | Complexité : Faible
  En cas d'oubli, l'organisateur reçoit un lien de réinitialisation par email
  valable 1 heure. Le lien est à usage unique.

[AUTH-04] Gestion Multi-Organisateurs            | Priorité : MOYENNE | Complexité : Faible
  L'administrateur système peut créer plusieurs comptes organisateurs via
  l'interface Django Admin. Chaque organisateur ne voit que ses propres
  activités.


------------------------------------------------------------------------
  MODULE 2 — GESTION DES ACTIVITÉS
------------------------------------------------------------------------

[ACT-01] Création d'une Activité                 | Priorité : HAUTE | Complexité : Faible
  L'organisateur remplit un formulaire avec :
    - Nom de l'activité (obligatoire)
    - Date de début et date de fin (avec sélecteur de date/heure)
    - Lieu (champ texte libre)
    - Description optionnelle
  À la validation, un token UUID unique est généré automatiquement et associé
  à l'activité.

[ACT-02] Génération du QR Code                   | Priorité : HAUTE | Complexité : Faible
  Après création de l'activité, un QR Code est généré automatiquement.
  Il encode l'URL unique du formulaire public :
    https://domaine.com/form/{token_uuid}
  Le QR Code est affiché à l'écran et peut être téléchargé en PNG ou imprimé
  directement depuis le navigateur.

[ACT-03] Liste des Activités — Tableau de Bord   | Priorité : HAUTE | Complexité : Faible
  L'organisateur dispose d'un tableau de bord listant toutes ses activités
  avec :
    - Nom, période, lieu, statut (Ouverte / Fermée / Terminée)
    - Nombre de participants enregistrés en temps réel
    - Actions rapides (voir, éditer, fermer, exporter)

[ACT-04] Modification d'une Activité             | Priorité : MOYENNE | Complexité : Faible
  L'organisateur peut modifier le nom, la période et le lieu d'une activité
  tant que la collecte est ouverte. Le token QR Code ne change pas lors d'une
  modification.

[ACT-05] Ouverture / Fermeture de la Collecte    | Priorité : HAUTE | Complexité : Faible
  L'organisateur peut manuellement ouvrir ou fermer le formulaire de collecte
  d'une activité. Quand l'activité est fermée, le formulaire public affiche un
  message d'information. La date de fin peut déclencher une fermeture
  automatique.

[ACT-06] Suppression d'une Activité              | Priorité : BASSE | Complexité : Faible
  Une activité peut être supprimée uniquement si elle ne contient aucun
  participant enregistré. Une confirmation en deux étapes est demandée. Les
  activités avec participants ne peuvent qu'être archivées.

[ACT-07] Détail d'une Activité                   | Priorité : HAUTE | Complexité : Faible
  Page dédiée affichant :
    - Les informations de l'activité
    - Le QR Code re-généré
    - La liste des participants avec pagination
    - Les boutons d'export


------------------------------------------------------------------------
  MODULE 3 — FORMULAIRE DE COLLECTE PUBLIC (PARTICIPANT)
------------------------------------------------------------------------
  Ce module est la partie visible par le participant lorsqu'il scanne le QR
  Code. Il doit être optimisé pour mobile (smartphone).

[FORM-01] Accès au Formulaire via QR Code        | Priorité : HAUTE | Complexité : Faible
  Le participant scanne le QR Code et accède directement au formulaire sans
  création de compte. Le système vérifie que le token est valide et que
  l'activité est ouverte. Si l'activité est fermée, un message explicatif est
  affiché.

[FORM-02] Champs du Formulaire de Collecte       | Priorité : HAUTE | Complexité : Faible
  Le formulaire contient les champs obligatoires suivants :
    - Nom
    - Prénom
    - Structure / Organisation
    - Fonction / Poste occupé
    - Numéro de téléphone Wave (format CI : +225 XX XX XX XX XX)
    - Adresse email (avec validation de format)
    - Numéro de la Carte Nationale d'Identité (CNI)
  L'horodatage (date et heure de soumission) est capturé automatiquement
  côté serveur.

[FORM-03] Upload Photo Recto CNI                 | Priorité : HAUTE | Complexité : Moyenne
  Le participant prend en photo ou sélectionne depuis sa galerie le recto de
  sa CNI. L'interface propose :
    - Un bouton "Prendre une photo" (ouverture de la caméra sur mobile)
    - Un bouton "Choisir depuis la galerie"
  Une prévisualisation de l'image est affichée avant soumission. L'image est
  compressée côté client (max 1 Mo) avant upload.

[FORM-04] Upload Photo Verso CNI                 | Priorité : HAUTE | Complexité : Moyenne
  Identique à FORM-03 mais pour le verso de la CNI. Les deux photos sont
  obligatoires avant soumission du formulaire.

[FORM-05] Validation en Temps Réel               | Priorité : HAUTE | Complexité : Faible
  Chaque champ est validé au fur et à mesure de la saisie :
    - Email : format valide
    - Téléphone : format ivoirien Wave
    - CNI : longueur et format
    - Photos : présence et taille
  Les erreurs sont affichées sous chaque champ de manière claire et explicite.

[FORM-06] Anti-Doublon par Numéro CNI            | Priorité : HAUTE | Complexité : Moyenne
  Un même numéro de CNI ne peut pas être enregistré deux fois pour la même
  activité. Si un doublon est détecté à la soumission, un message informatif
  est affiché avec la possibilité de mettre à jour les informations existantes.

[FORM-07] Page de Confirmation                   | Priorité : HAUTE | Complexité : Faible
  Après soumission réussie, le participant voit une page de confirmation
  affichant :
    - Un message de succès
    - Un récapitulatif de ses informations (sans les photos)
    - La date et heure d'enregistrement
  Aucun bouton de retour au formulaire n'est proposé (pour éviter les doublons
  accidentels).

[FORM-08] Mode Hors-Ligne Partiel                | Priorité : MOYENNE | Complexité : Moyenne
  Si la connexion est perdue pendant la saisie, les données du formulaire
  (hors photos) sont sauvegardées dans le localStorage du navigateur. À la
  reconnexion, le formulaire est pré-rempli automatiquement avec les données
  sauvegardées.

[FORM-09] Interface Responsive Mobile-First      | Priorité : HAUTE | Complexité : Faible
  Le formulaire est conçu en priorité pour mobile :
    - Boutons larges (min 48px)
    - Texte lisible (min 16px pour éviter le zoom iOS)
    - Upload photo optimisé pour l'appareil photo du téléphone
    - Chargement rapide (< 3 secondes sur 3G)


------------------------------------------------------------------------
  MODULE 4 — TRAITEMENT DES PHOTOS CNI
------------------------------------------------------------------------

[IMG-01] Compression Côté Client                 | Priorité : HAUTE | Complexité : Faible
  Avant upload, les photos sont compressées via browser-image-compression.
    - Taille cible : maximum 800 Ko par photo
    - Format conservé : JPEG
    - Qualité : 85%

[IMG-02] Redimensionnement Côté Serveur          | Priorité : HAUTE | Complexité : Moyenne
  Après réception, le serveur redimensionne les images via Pillow (Python)
  aux dimensions standardisées pour insertion dans le PDF.
    - Dimensions cibles : 1010 x 638 pixels
      (ratio carte bancaire 85.6 x 54 mm à 300 dpi)
    - Le recadrage conserve le ratio sans déformation.

[IMG-03] Organisation du Stockage               | Priorité : HAUTE | Complexité : Faible
  Les photos sont stockées dans une arborescence structurée :
    media/cni/{annee}/{activite_id}/{participant_id}/recto.jpg
    media/cni/{annee}/{activite_id}/{participant_id}/verso.jpg
  Les noms de fichiers sont normalisés (pas de caractères spéciaux). L'accès
  aux photos est protégé (non accessible publiquement via URL directe).

[IMG-04] Vérification de l'Intégrité            | Priorité : HAUTE | Complexité : Faible
  Le serveur vérifie que chaque upload est bien une image (MIME type), non
  corrompue, et de dimensions minimales (au moins 400 x 250 pixels). Un
  message d'erreur explicite est renvoyé si la vérification échoue.


------------------------------------------------------------------------
  MODULE 5 — EXPORTS ET GÉNÉRATION DE DOCUMENTS
------------------------------------------------------------------------

[EXP-01] Export Excel de la Liste des Participants  | Priorité : HAUTE | Complexité : Moyenne
  L'organisateur peut exporter un fichier .xlsx contenant tous les participants
  d'une activité.
  Format : une ligne par participant avec colonnes :
    N°, Nom, Prénom, Structure, Fonction, Téléphone Wave, Email, N° CNI,
    Horodatage
  Mise en forme :
    - En-tête colorée
    - Colonnes auto-dimensionnées
    - Alternance de couleurs par ligne
    - Feuille récapitulative de l'activité en onglet 1

[EXP-02] Export PDF — Fiche CNI Individuelle    | Priorité : HAUTE | Complexité : Haute
  Pour chaque participant, génération d'un PDF d'une page contenant :
    - En-tête avec nom de l'activité et date
    - Informations du participant (nom, prénom, structure, fonction, tel,
      email, CNI)
    - Photo recto CNI positionnée précisément (dimensions standardisées)
    - Photo verso CNI positionnée précisément
    - Horodatage de l'enregistrement
    - Pied de page avec numéro de page

[EXP-03] Export PDF — Liste de Présence Signée  | Priorité : HAUTE | Complexité : Moyenne
  Génération d'un PDF de liste de présence au format portrait A4, avec :
    - En-tête : nom de l'activité, lieu, période
    - Tableau avec colonnes : N°, Nom, Prénom, Structure, Fonction,
      Téléphone, Signature (colonne vide)
    - Pied de page avec date de génération

[EXP-04] Export ZIP — Toutes les Fiches CNI     | Priorité : HAUTE | Complexité : Moyenne
  L'organisateur peut télécharger en un clic un fichier ZIP contenant les
  fiches PDF CNI de tous les participants de l'activité.
    - Nommage ZIP : {nom_activite}_{date}_fiches_cni.zip
    - Nommage PDF : {nom}_{prenom}_cni.pdf

[EXP-05] Filtres avant Export                   | Priorité : MOYENNE | Complexité : Moyenne
  Avant de lancer un export, l'organisateur peut filtrer les participants par :
    - Structure
    - Date d'enregistrement (entre deux dates)
    - Statut de complétude (CNI complète / incomplète)

[EXP-06] Historique des Exports                 | Priorité : BASSE | Complexité : Faible
  Chaque export généré est tracé dans un journal :
    date, type d'export, nombre d'entrées, utilisateur ayant déclenché.
  Accessible depuis la page de détail de l'activité.


------------------------------------------------------------------------
  MODULE 6 — TABLEAU DE BORD & PILOTAGE
------------------------------------------------------------------------

[DASH-01] Vue d'Ensemble des Activités           | Priorité : HAUTE | Complexité : Faible
  Page principale après connexion listant toutes les activités de l'organisateur
  avec :
    - Cartes récapitulatives (nom, lieu, dates, statut)
    - Compteur de participants en temps réel
    - Barre de recherche et filtres par statut

[DASH-02] Compteur de Participants en Temps Réel | Priorité : MOYENNE | Complexité : Faible
  Sur la page de détail d'une activité, le compteur de participants se
  rafraîchit toutes les 30 secondes automatiquement (polling). L'organisateur
  peut voir les nouvelles entrées sans recharger la page.

[DASH-03] Liste des Participants avec Pagination | Priorité : HAUTE | Complexité : Faible
  Tableau paginé (20 par page) affichant tous les participants avec :
    - Avatar (initiales), nom, prénom, structure, téléphone, horodatage
    - Statut photos CNI (complètes / manquantes)
    - Actions (voir fiche, exporter PDF individuel)

[DASH-04] Fiche Détaillée d'un Participant       | Priorité : HAUTE | Complexité : Faible
  Vue complète d'un participant :
    - Toutes ses informations
    - Miniatures des photos CNI cliquables (zoom)
    - Bouton de génération du PDF individuel
    - Horodatage précis

[DASH-05] Statistiques par Activité              | Priorité : MOYENNE | Complexité : Moyenne
  Panneau de statistiques affichant :
    - Nombre total de participants
    - Répartition par structure (graphique)
    - Nombre de CNI complètes vs incomplètes
    - Évolution des inscriptions dans le temps (courbe)


================================================================================
  3. EXIGENCES NON FONCTIONNELLES
================================================================================

3.1 Sécurité
-------------
  - Authentification par JWT avec expiration configurable (défaut : 8h)
  - Formulaire public sécurisé par token UUID opaque (sans authentification)
  - Protection CSRF sur toutes les routes POST
  - Validation et assainissement de toutes les entrées côté serveur
  - Stockage des photos hors de la racine web publique
  - HTTPS obligatoire en production (certificat Let's Encrypt)
  - Hachage des mots de passe avec bcrypt (géré par Django)
  - Logs d'accès et d'erreurs conservés 90 jours


3.2 Performance
----------------
  - Temps de chargement du formulaire public : < 3 secondes sur 3G
  - Génération d'un PDF individuel            : < 5 secondes
  - Génération du ZIP complet (50 parts.)     : < 30 secondes
  - Export Excel (200 participants)           : < 10 secondes
  - API : temps de réponse moyen              : < 500 ms


3.3 Compatibilité
------------------
  - Formulaire public    : Chrome mobile, Safari iOS, Firefox mobile
  - Interface organisateur : Chrome, Firefox, Edge (desktop)
  - Serveur              : Ubuntu 22.04 LTS


3.4 Accessibilité & UX
-----------------------
  - Interface entièrement en langue française
  - Formulaire mobile-first avec éléments tactiles min. 48px
  - Messages d'erreur explicites en français
  - Retours visuels (loaders, messages de succès) sur toutes les actions


3.5 Disponibilité & Sauvegarde
-------------------------------
  - Disponibilité cible                  : 99% (hors maintenance planifiée)
  - Sauvegarde PostgreSQL                : automatique quotidienne (pg_dump)
  - Sauvegarde fichiers media (photos)   : hebdomadaire
  - Rétention des sauvegardes            : 30 jours

  5. PLAN DE DÉVELOPPEMENT
================================================================================

  Le projet est découpé en 6 sprints de 1 semaine chacun. Chaque sprint a des
  livrables précis, testables et déployables.

════════════════════════════════════════════════════════════════════════════════
  SPRINT 1 — Setup & Infrastructure                                  (Semaine 1)
════════════════════════════════════════════════════════════════════════════════

  Objectif :
    Avoir les deux projets (backend + frontend) fonctionnels en local et en
    production, avec la base de données connectée et Nginx configuré.

  Tâches Backend :
    1. Initialisation du projet Django (apps : accounts, activites,
       participants, exports)
    2. Configuration PostgreSQL + migrations initiales
    3. Installation et configuration de Django Ninja
    4. Mise en place des variables d'environnement (.env) avec python-dotenv
    5. Configuration du stockage média local (photos CNI)
    6. Setup Gunicorn + fichier de service systemd

  Tâches Frontend :
    1. Initialisation du projet React avec Vite
    2. Installation de MUI, React Router, Axios, React Query,
       React Hook Form, Zod
    3. Configuration du thème MUI (couleurs, typographie)
    4. Mise en place du routing (routes publiques / protégées)
    5. Configuration du proxy Axios vers l'API

  Tâches Infrastructure :
    1. Configuration du serveur Ubuntu 22.04
    2. Installation et configuration de Nginx
    3. Obtention du certificat SSL (Let's Encrypt / Certbot)
    4. Script de déploiement (git pull + build + restart)

  Livrables :
    - API Django accessible sur https://api.domaine.com/api/docs
    - Frontend React accessible sur https://domaine.com
    - Page de connexion affichée (sans logique encore)
    - Base de données PostgreSQL vide mais opérationnelle


════════════════════════════════════════════════════════════════════════════════
  SPRINT 2 — Authentification & Gestion des Activités               (Semaine 2)
════════════════════════════════════════════════════════════════════════════════

  Objectif :
    L'organisateur peut se connecter, créer des activités et obtenir son QR Code.

  Tâches Backend :
    1. Modèle User + migration
    2. Endpoints JWT : POST /api/auth/login, /api/auth/refresh, /api/auth/logout
    3. Modèle Activite + migration
    4. Endpoints CRUD activités : GET/POST /api/activites/
                                  GET/PUT/DELETE /api/activites/{id}/
    5. Endpoint génération QR Code : GET /api/activites/{id}/qrcode/
    6. Middleware de vérification JWT sur routes protégées

  Tâches Frontend :
    1. Page Login avec formulaire (React Hook Form + Zod) + gestion JWT
    2. Hook useAuth + contexte d'authentification global
    3. Route guard pour pages protégées
    4. Page Dashboard (liste des activités) avec MUI DataGrid
    5. Dialog de création d'activité (formulaire + date pickers MUI)
    6. Page détail activité avec affichage QR Code (react-qr-code)
    7. Bouton téléchargement QR Code en PNG

  Livrables :
    - Login fonctionnel avec token JWT
    - Création d'activité via l'interface
    - QR Code affiché et téléchargeable
    - Dashboard listant les activités


════════════════════════════════════════════════════════════════════════════════
  SPRINT 3 — Formulaire Public & Upload CNI                         (Semaine 3)
════════════════════════════════════════════════════════════════════════════════

  Objectif :
    Le participant peut scanner le QR Code, remplir le formulaire, uploader ses
    photos CNI et recevoir une confirmation.

  Tâches Backend :
    1. Modèle Participant + migration
    2. Endpoint vérification token : GET /api/public/activite/{token}/
    3. Endpoint soumission : POST /api/public/activite/{token}/participer/
    4. Validation serveur (champs, format téléphone/email, présence photos)
